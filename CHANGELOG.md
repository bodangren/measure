### Bug Fixes

* **guard phase start:** the closeout guard no longer denies a task change to `[~]` in phase N+1 while the heading of phase N has no `[checkpoint: <sha>]`. Phases can run at the same time, so the deny was a false block: in Workbooks, it stopped Task 6.1 of `storytime_l2_unit2_20261106` while Phase 5 had not started. The edit is now allowed, and the agent gets a note that names the checkpoint protocol (`phaseStartNote` in the shared core). The mod, the OpenCode plugin, and the DSH plugin change together. Track `guard_phase_start_20261109`.
* **guard session track:** the task note of `opencode-measure-guard` now names the track of each session. Before, it named the first `[~]` track with a `[~]` task for every session, so in a registry with many `[~]` tracks each session got the same wrong track. A session names its track with a prompt, its title, or a file that it writes. A session that names no track gets a short list of the tracks with a `[~]` task, or of the `[~]` tracks when none has a task. A project with one track in progress keeps its note, and the guards keep the project-wide track. `plugins/opencode-measure-guard/tests/session-track.test.ts` (19 cases). Track `guard_session_track_20261109`.
* **gate track scope:** the `spec-review` gate, the `jr-green` HEAD check, and the `ux-browser-review` gate now use the track scope of the `mid-red` gate. The new `ux-paths --track <id>` option uses it too. When `baseline..HEAD` holds commits of other tracks, each check reads only the commits of the track under check. In this scoped mode, each check prints each skipped commit as an `INFO:` line, and `ux-paths` prints these lines to stderr. The `jr-green` gate fails when the range has no commit of the track, and the `spec-review` gate still runs its tree diff first, so a git failure still fails it. A commit with no id or an unknown id still counts as a commit of the track. Cause: in the Monorepo, the spec-review gate of one track failed on six files of a parallel login track. `tests/spec_review_gate/test_gate_track_scope.py` (19 cases). Track `gate_track_scope_20261108`.
