## Round 1

Date: 2026-11-07
Reviewer: subagent (fresh context, default model)

### What this track proposes

This track makes the guard mode effective per repository: the persisted `repos.json` override and an in-memory session override compose above the profile config, are read per call through one `deps.modeOf(root)` seam by the guards, the note/reminder, the turn-end hold, and the client view, and are exposed in the state route, the band, `measure_status`, and `/measure-status`. It adds `/measure-mode` to report, set, and clear the session and repository overrides, and the read-only `/measure-verify` to report the active plan's git-backed problems plus the active track's `metadata actual_tasks` verdict, failing open instead of throwing. Docs, a live strict-deny probe with its run record, and the track closeout complete it, all adapter-side with no shared-core change, no new dependency, and both parity gates green.

### How the current system works, per this spec

The adapter resolves `config.mode` once at `apply` (`parseModeOf`) and hands that static value to every guard, the `measure_status` tool, and the state route, while `Repos.modeOf`/`setMode` in `src/state.js` are exercised only by tests and no command changes the mode. The git-backed task problems run only at `agent/turn-stopping` and the closeout `metadata.json` check only inside a `tracks.md` close edit, so both are turn-end or edit-triggered. The current host commands are `measure-off`, `measure-on`, `measure-status`, and `measure-goal` plus the eight workflow commands, and the state route and band carry no mode.

## Round 2

Date: 2026-11-07

### What this track proposes
The track makes the DeepSeek Harness adapter's guard mode effective per canonical root by composing a persisted repository override, an in-memory session override, and the profile config default, and adds a `/measure-mode` chat command that reports, sets, or clears those overrides. It exposes the effective mode's value and source in the client state route, the band, `measure_status`, and `/measure-status`, with a localized label in the band. It adds a read-only `/measure-verify` command that refreshes the snapshot, probes git once, reuses the end-of-turn `shaProblems`, and adds a `metadata.json` verdict for the active track, returning a string report and mutating nothing. The track also promises tests, docs, a live check, and a closeout, and claims no shared-core change, no new dependency, no CLI contract test change, and both parity gates green.

### How the current system works, per this spec
The DSH adapter reads the guard mode once from the profile config (`parseModeOf(config.mode)`) and passes that static value to the guards, while `src/state.js` already persists a per-root `mode` in `repos.json` that nothing reads. The git-backed task problems (`shaProblems`) run only at `agent/turn-stopping`, and the closeout `metadata.json` check (`closeoutMetadataCheck`) runs only inside a `tracks.md` close edit, so an operator cannot ask for the verification on demand. The plugin also has a client state route and band, a `measure_status` tool, a bypass store, a shared `.ts` core that both parity gates compare across the adapter packages, `node --test` for the plugin, and separate environment-CLI and spec-review-gate suites.
